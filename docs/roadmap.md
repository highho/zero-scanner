# Zero 后续开发案

> 基线：v1.2.0（2026-11-28）。本文档记录差距分析与三个版本的规划，随实现进度更新。

## 一、现状

| 维度 | 数字 |
| --- | --- |
| 源码 | 30 个模块，20,212 行（ui.rs 4,872 / app.rs 3,115 / theme.rs 1,256 / mcp.rs 1,169） |
| 界面 | 15 个工作区 |

## 二、差距：按玩家真正会用的顺序排

Cheat Engine 的实战路径是：**找值 → 找基址 → 找出谁在改它 → 做成下次还能用的东西**。

| 环节 | CE 有什么 | Zero 现在 | 缺口 |
| --- | --- | --- | --- |
| 找值 | 9 种扫描 | 9 种 | 齐 |
| 找基址 | 指针扫描 + 指针地图（存盘、换地址重扫） | 一次性扫描，结果不存盘 | 中 |
| **找出谁在改** | **硬件断点 / 内存断点，命中记录指令与寄存器** | **完全没有调试器** | **高（最大缺口）** |
| 做成可复用 | CT 表格 + 训练器导出 + 完整 Lua API | CT 读写 + 6 个 Lua 全局函数 | 高 |
| 反作弊对抗 | 内核驱动 | 明确不做 | 不做 |

结论：**1.3 补调试器，1.4 补可携带性，1.5 补稳定性。**

## 三、1.3 「谁在改它」

### 目标

回答一个具体问题：这个地址是被哪条指令改的？那条指令长什么样？当时的寄存器是什么？

### 功能

1. **硬件断点（DR0–DR3）**
   - 对某个地址设写入 / 读写断点，每线程最多 4 个
   - 命中时记录：指令地址、反汇编文本、寄存器快照（RAX–R15、RIP、RFLAGS）、写入值
2. **找出是什么改写了这个地址**
   - 地址列表右键直接发起，结果进一张命中历史表
   - 历史按时间倒序，同一条指令重复命中合并计数
3. **命中 → 反汇编联动**
   - 点一条命中跳到反汇编页并定位到该指令
   - 可选：在该指令处建议「打补丁跳过它」
4. **安全边界**
   - 只对自己 attach 的进程设断点
   - 断点在会话结束或进程退出时全部清除
   - 目标线程上下文恢复原值

### 验收

- 对内置练习靶场设写入断点，命中次数与靶场自增次数一致（自检断言）
- 命中记录里的 RIP 落在模块内，且反汇编长度有效
- 四个断点同时设置不互相干扰
- 关闭调试器后目标进程无残留

### 风险

- 需要 `DebugActiveProcess` + `WaitForDebugEvent` 的独立线程；调试事件循环容易和 UI 线程打架 → 用后台线程 + channel 回传
- 某些进程会拒绝被调试（已在被调试 / 受保护）→ 明确报错，不静默失败

## 四、1.4 「能带走」

### 目标

把一次调试的成果变成下次还能用的东西。

### 功能

1. **Lua API 补到 CE 常用集**
   - `autoAssemble` / `AOBScan` / `registerSymbol` / `readPointer` / `writePointer` / `allocateMemory` / `createTimer` / `getAddress(模块名)`
   - 目标：能直接跑网上常见的 CE 表脚本
2. **训练器导出**
   - 地址列表 + 补丁 + 热键 → 一个独立 exe（或 `.ct` + 一键启动脚本）
   - 导出前校验：所有地址可解析、所有补丁可还原
3. **指针地图存盘**
   - 扫描结果存盘，换一个地址后可直接重扫，不用重新扫全内存
4. **插件能力扩展**
   - struct 模板：JSON 描述字段布局，按模块签名匹配
   - 游戏配置包：每个游戏一套扫描参数与热键

### 验收

- 用 3 个真实 CE 脚本样本跑通，样本放在 `examples/`
- 导出的训练器在干净目录里能启动、能读写、能还原
- 指针地图存盘后重新加载，解析结果与内存中一致

## 五、1.5 「更稳」

- **变速齿轮**改计时器钩子（现在靠挂起 / 恢复线程，目标里的计时与音频会一起停）
- **更新包校验**补 sha256（现在只查 MZ 头）
- **内存区域热图**：哪些页在频繁变化，一屏看出来
- **附加失败诊断**：受保护进程 / 完整性级别不够 / 反作弊，给出具体原因而不是一句失败

## 六、明确不做

- 内核驱动、绕过反作弊
- DLL 注入
- 云端大模型
- 联机游戏用途

## 七、排期建议

| 版本 | 主题 | 主要工作量 | 依赖 |
| --- | --- | --- | --- |
| 1.3 | 调试器 | 新增 `debugger.rs`（约 600 行）+ 断点页 + 自检 | 无 |
| 1.4 | 可携带 | `lua.rs` 扩展 + 训练器导出 + 指针地图存盘 + 插件扩展 | 1.3 的命中数据 |
| 1.5 | 稳定性 | `speed.rs` 重写 + 更新校验 + 热图 | 无 |

## 八、验证策略（沿用现有纪律）

每个版本交付时必须同时给出：

1. `--selftest` 新增断言全 PASS（当前 136 项）
2. 至少一张新页面截图（`--demo` 实渲）
3. 一条真实 E2E（对练习靶场或 `e2e_target.py`）
4. README 与 docs 同步更新
5. 安装包重新构建并真装一遍
